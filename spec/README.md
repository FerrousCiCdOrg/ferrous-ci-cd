## Design Principles

Ferrous CI/CD is built on the following design principles:

1. **Domain-Driven Design (DDD)**
   - Domain model-centered design
   - Business logic aggregated in the domain layer
   - Clear bounded contexts

2. **Clean Architecture**
   - Clear dependencies between layers
   - Domain layer does not depend on other layers
   - Abstraction through interfaces

3. **Event-Driven Design**
   - Loose coupling through domain events
   - Support for asynchronous processing
   - Ensures extensibility

4. **Type Safety**
   - Leverages Rust's type system
   - Expression of domain concepts through value objects
   - Compile-time error detection

## Glossary

- **Pipeline**: CI/CD pipeline definition. A collection of stages and jobs.
- **Build**: An execution instance of a pipeline.
- **Stage**: An execution phase of a pipeline. Contains multiple jobs.
- **Job**: The smallest unit of executable task.
- **Agent**: A worker node that executes builds.
- **Project**: A unit that manages repositories and pipelines.
- **Artifact**: Outputs generated by builds.
- **Pipeline definition**: The text or code a pipeline is written in.
- **IR (intermediate representation)**: `PipelineConfig`, the single form every pipeline definition is lowered into before anything acts on it.
